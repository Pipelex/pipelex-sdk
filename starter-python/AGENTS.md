# Agent instructions — pipelex-starter-python

The full project guide for AI coding agents is [`CLAUDE.md`](CLAUDE.md) — read it; everything there applies regardless of which agent you are. The rules below are the ones that cause real damage when missed:

- **Never edit anything under `widget/generated/`** — not even a reformat. Every artifact carries a stamp with its own content hash and a sibling `codegen.lock` hashes them all, so any edit makes `tests/unit/test_generated_clients.py` fail with a drift report. Customize by wrapping the model from your own code instead. Relatedly, `widget/generated` is excluded from ruff on purpose and is fully type-checked on purpose — do not "fix" either.
- **After editing anything under `widget/methods/`, run `make codegen`** and commit the regenerated tree in the same commit. Regeneration needs `PIPELEX_API_KEY` and nothing else: the projection happens in the hosted API through `pipelex-sdk`, so there is no `pipelex` runtime to install.
- **After any code change, run `make agent-check` and `make agent-test`.** Do not declare a task done until both pass. `agent-check` formats as it goes — don't hand-edit to satisfy ruff — and `agent-test` is silent on success and prints everything on failure, which is why it is the one to run rather than `make test`.
- **`pipelex` is not a dependency and must not become one.** This starter calls the hosted API through `pipelex-sdk`, and nothing here reaches for a `pipelex` CLI any more: `make codegen` goes through the hosted codegen route and `make codegen-check` runs the SDK's own offline check, which `tests/unit/test_generated_clients.py` runs too. Adding the runtime to get a gate would reverse the decision this starter exists to demonstrate.
- **Never introduce a shared runner across the execution modes.** `widget/<mode>/cli.py` is a copy-paste unit and the near-duplication between the three is the pedagogy; the only shared modules are the ones orthogonal to execution (`inputs.py`, `outputs.py`, `errors.py`, `usage.py`). `tests/unit/test_mode_symmetry.py` guards the matrix.
- **No hand-written output shapes.** Narrow a run's `main_stuff` with the generated model (`ExtractedEntities.model_validate(main_stuff)`), and read a plural output through `widget/outputs.py`'s `list_items` rather than declaring which of its two wire shapes arrived.
- **The project-name placeholder is an ordinary English word, so never write that word in ordinary prose.** `/bootstrap` substitutes every occurrence of the template's stand-in name and aborts the whole run if any survives, so a sentence using that word in its generic sense fails a user's bootstrap. The plural aborts too, and deliberately: no substitution rule matches it, so the survivor check is what stands between a stray plural and a half-renamed project. Say "the package", "the project" or "the CLI" instead. In `pyproject.toml` the bar is higher still: a bare occurrence there is refused rather than guessed at, since the file puts both name forms in bare-string positions, so name a path (`widget/methods`) or a module (`widget.cli`) and never the token alone.
- **Do not move or delete the `# add-method:imports` and `# add-method:commands` anchors** in the three mode files. `make add-method` inserts at them, the prose after each token is free to reword, and `tests/unit/test_add_method.py` reads the real files so a lost anchor fails the suite.
- **Never commit a planning note or campaign document to this template.** It is consumed through "Use this template", so anything it tracks is copied into somebody's new project. The template's own campaign documents live in the workspace wip repository (`wip/<topic>/` at the workspace root), and the workspace guard refuses a write into a `wip/` here.

A method that lives **on the platform** (a catalog id) or **in a published package** (an address) is wired in with `make add-method METHOD=<mt_… | github.com/owner/repo[/package][@tag]>` rather than by hand — see [`docs/add-method.md`](docs/add-method.md). A method whose bundle you have on disk goes under `widget/methods/<name>/` and through `make codegen` instead.

Reference docs live in [`docs/`](docs/) — [`docs/codegen.md`](docs/codegen.md) for the generated-types design and the two source kinds, [`docs/cli-architecture.md`](docs/cli-architecture.md) for why the execution mode is the command group, [`docs/add-method.md`](docs/add-method.md) for the scaffolder.

## Taking this pattern into a project you already have

**This repo carries no transplant guide, and that is a decision rather than an omission.** `pipelex-starter-js` has one — `docs/adopt-in-an-existing-project.md` — because on that side there is a real body of code to move: seven script files, a `tsconfig.scripts.json`, and a `src/lib/` server pattern that exists nowhere else. In Python there is no such kit. `pipelex-sdk` already ships the generator's writer (`write_codegen_tree`) and the offline drift check (`run_codegen_check`), so `scripts/codegen.py` is a discovery loop over a package you install rather than machinery you copy, and the narrowing a TypeScript project needs an adapter layer for is one `Model.model_validate(...)` call here.

So the transplant is: add `pipelex-sdk`, put the bundle under `<package>/methods/<name>/`, generate into `<package>/generated/<name>/`, exclude that directory from ruff while keeping it in pyright and mypy, and call the method with `Model.model_validate(results.main_stuff)`. **The `/pipelex-integrate` skill does exactly that and detects the project it is doing it to** — package manager, import package, formatter, type-checker scope, whether the project is packaged — which a page in this repo could only describe in the abstract. Writing that page here would duplicate a moving surface and go stale the first time the skill changed, which is the failure this workspace has been bitten by before.

The five bullets above are the whole of what a reader without the skill needs, and **this repository is the worked example of each one**: `pyproject.toml` for the ruff exclusion beside the pyright and mypy scopes, `scripts/codegen.py` for the generation call, `widget/attended/cli.py` for a call site, `tests/unit/test_generated_clients.py` for the gate. Read those four files in that order.
